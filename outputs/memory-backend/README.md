# omi · 服务端规则验证 02

本轮将权限规则从浏览器模拟移至 Python 服务端应用，使用真实 SQLite 数据库。仍仅使用 20 条虚构记录，不接入模型。三个核心交互入口及产品定位保持原方案。

## 运行测试

需要 Python 3.9 或更高版本，无第三方依赖。在本目录执行：

```sh
python3 test_backend.py
```

每项测试创建真实临时数据库、签发随机实验凭证、通过 WSGI 请求接口操作，最后销毁数据库。`test-results.json` 保存本次运行结果。凭证仅在测试内存中使用，不输出或保存明文；服务端保存哈希和到期时间。

## 当前接口

所有接口要求 `Authorization: Bearer <实验凭证>`。凭证由离线测试初始化签发，没有公开的“选择 A 登录”接口。

- `GET /v1/me`：查看凭证对应身份。
- `GET /v1/messages/{id}`：查阅有权访问的原始记录。
- `POST /v1/messages`：提交 `space_id`、`text`、`client_id`，发送者由服务端确定。
- `DELETE /v1/messages/{id}`：删除本人发送的记录及本实验内的派生内容。
- `POST /v1/search`：提交 `context`（personal/shared/assistant）和 `query`；服务端计算范围，不接受客户端扩大到其他人的空间。
- `GET /v1/gifts/gift01`：只返回明确授权的旅行片段，不返回完整私人来源。
- `DELETE /v1/gifts/gift01`：只有发送者可以撤销。

`assistant` 是私人单聊检索上下文，包含本人个人记录、本人私人单聊及有效共同空间；`shared` 只检索共同记录。礼物不自动加入问答检索，避免授权用途扩张。

## 验证边界

这是后端可行性实验，不是已上线 API，也不是生产版本。测试直接执行真实 WSGI 请求处理函数，没有启动网络监听，不等于完成 HTTP/TLS 或浏览器联调。

使用 SQLite 是为了无依赖复现实验，不代表替换已提议的 PostgreSQL/FastAPI 生产架构。所有请求以短事务串行化权限检查和读写，适合本轮一致性验证，不能用于推断生产吞吐。Worker 仅复制原文形成关键词检索条目，不是 AI 摘要、语义检索或真实分布式队列。

来源删除后清空可查询正文与实验索引，不承诺 SQLite 文件空闲页、系统备份或已有下载副本的物理擦除。尚无媒体、向量数据库或跨服务缓存，不能宣称这些链路已验证。

正式版仍需微信身份兑换、会话生命周期、数据库 RLS、媒体鉴权、邀请并发、用途化授权、部署和恢复测试。模型服务暂未选定，因此本轮不评估自动分类、用户画像准确度和关系建议质量。
